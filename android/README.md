# پیام‌نگار امن — نسخهٔ اول اندروید (SMS)

> **وضعیت این بسته:** سورس مستقل نسخهٔ اول؛ APK آزمایشی Debug از GitHub Actions قابل ساخت است، اما نصب/مجوزها و تبادل SMS هنوز روی گوشی واقعی به‌طور کامل تأیید نشده‌اند. ممیزی امنیتی مستقل انجام نشده است.

## محدودهٔ نسخهٔ اول

- استفادهٔ خصوصی فقط میان دو نفر؛ بدون حساب، ثبت‌نام، کد دعوت یا سرور.
- ارسال پیام از داخل برنامه با SMS.
- دریافت پیام‌های اختصاصی پیام‌نگار از طریق Android `SMS_RECEIVED`، بازسازی پیام چندبخشی، ذخیرهٔ محلی و نمایش اعلان.
- نمایش متن پیام فقط بعد از واردکردن عبارت محرمانهٔ مشترک.
- عبارت محرمانه همراه SMS فرستاده نمی‌شود و در پایگاه داده یا تنظیمات برنامه ذخیره نمی‌شود.
- متن پیام فقط به‌صورت بستهٔ رمز‌شده در پایگاه دادهٔ محلی ذخیره می‌شود.
- نسخهٔ وب فعلی و مخزن GitHub قبلی جزو این پروژه نیستند و تغییر داده نشده‌اند.

## آنچه در نسخهٔ اول وجود ندارد

ارتباط اینترنتی، API یا سرور، ثبت‌نام و دعوت‌نامه، همگام‌سازی ابری، تغییر خودکار بستر ارتباطی، تبادل کلید با QR، ارسال فایل/عکس و انتشار در Google Play در این نسخه پیاده‌سازی نشده‌اند. این موارد برای نسخهٔ دوم یا تصمیم بعدی باقی می‌مانند.

## ساختار فنی

- زبان: Java
- رابط: Android Views بومی؛ بدون وابستگی به Expo یا کتابخانهٔ UI خارجی
- `minSdk`: 26 (Android 8.0)
- `compileSdk` / `targetSdk`: 36
- Android Gradle Plugin: 9.5.0
- Gradle: 9.6.0
- JDK: 17
- هیچ مجوز `INTERNET` در Manifest تعریف نشده است.

### رمزنگاری و سازگاری با نسخهٔ وب

بستهٔ پیام با قالب فعلی نسخهٔ وب سازگار طراحی شده است:

- PBKDF2-HMAC-SHA-256 با ۳۱۰٬۰۰۰ تکرار
- AES-256-GCM با برچسب اصالت ۱۲۸ بیتی
- salt تصادفی ۱۶ بایتی و IV تصادفی ۱۲ بایتی
- رمزگذاری UTF-8 و Base64URL بدون padding
- ساختار JSON شامل `v`, `alg`, `iter`, `salt`, `iv`, `ct`

این تطبیق در آزمون متقابل Java و WebCrypto بررسی شده است؛ به معنی ممیزی امنیتی کامل یا تأیید امنیت عبارت انتخابی نیست. عبارت کوتاه یا قابل حدس، حتی با KDF، در برابر حدس آفلاین مقاوم نیست. از عبارت طولانی، تصادفی و غیرقابل حدس استفاده کنید.

### انتقال پیام از طریق SMS

- هر پیام رمز‌شده به فریم‌های متنی با پیشوند `PN1` تقسیم می‌شود.
- هر فریم جداگانه به‌صورت یک SMS ارسال می‌شود؛ کد برنامه برای هر فریم طول یک SMS را با API اندروید کنترل می‌کند.
- ظرفیت برنامه حداکثر ۲۰ فریم برای هر پیام است. پیام بلندتر رد می‌شود.
- قطعات با شناسهٔ تصادفی ۶۴ بیتی و شمارهٔ بخش بازسازی می‌شوند؛ دریافت قطعات خارج از ترتیب پشتیبانی می‌شود.
- قطعات ناقص پس از ۷۲ ساعت پاک می‌شوند.
- هر فریم یک پیامک جداگانه است و هزینه مطابق تعرفهٔ اپراتور محاسبه می‌شود. پیش از ارسال، تعداد پیامک‌ها به کاربر نشان داده می‌شود.
- وضعیت «ارسال‌شده» فقط یعنی اندروید ارسال به سرویس پیامک را پذیرفته است؛ **تحویل به گوشی مقصد تضمین یا تأیید نمی‌شود**.

## نصب خصوصی و مجوزهای پیامک

`SEND_SMS` و `RECEIVE_SMS` در اندروید مجوزهای محدودشده‌اند. نصاب باید در زمان نصب آن‌ها را allowlist کند. نصب با لمس فایل APK یا نصب‌کنندهٔ عمومی را برای این دو مجوز، مسیر قطعی فرض نکنید. برای دو گوشی شخصی، مسیر پیشنهادی این بسته نصب با ADB است.

1. Android SDK Platform-Tools را روی رایانه نصب کنید و USB debugging را در گزینه‌های توسعه‌دهندهٔ هر گوشی فعال کنید.
2. گوشی را با USB وصل کنید و در ترمینال اجرا کنید:

   ```bash
   adb devices
   adb install -r -g app-debug.apk
   ```

3. همین روند را برای گوشی دوم تکرار کنید.
4. با اولین بازکردن گفتگو، برنامه وضعیت هر دو مجوز `SEND_SMS` و `RECEIVE_SMS` را بررسی و در صورت نیاز درخواست می‌کند. اگر Android درخواست را به‌دلیل محدودیت نصب رد کند، برنامه راهنمای بازکردن App info و گزینهٔ «Allow restricted settings» را نشان می‌دهد. پس از فعال‌سازی از Settings به برنامه برگردید و مجوزهای SMS را بررسی کنید.
5. مجوز اعلان (`POST_NOTIFICATIONS`) جداگانه و اختیاری درخواست می‌شود؛ ردکردن آن دریافت SMS را متوقف نمی‌کند، اما اعلان نمایش داده نمی‌شود.
6. شمارهٔ مخاطب را در هر گوشی با علامت `+` و کد کشور ثبت کنید؛ ارقام فارسی هم پذیرفته می‌شوند.
7. در گوشی‌های دوسیم‌کارته، سیم‌کارت پیش‌فرض ارسال پیامک را در تنظیمات خود گوشی مشخص کنید.

فرمان `adb install` در پیاده‌سازی فعلی AOSP مجوزهای محدودشده را به‌طور پیش‌فرض در فهرست مجاز نصب قرار می‌دهد و گزینهٔ `-g` مجوزهای runtime درخواستی را اعطا می‌کند؛ سازندهٔ گوشی ممکن است رفتارهای تکمیلی داشته باشد، بنابراین وضعیت نهایی باید در خود برنامه و روی هر دو گوشی بررسی شود.

### رفتار برنامه در جایگاه غیر پیش‌فرض SMS

نسخهٔ اول خودش را به‌عنوان برنامهٔ پیش‌فرض پیامک گوشی ثبت نمی‌کند. فقط پیام‌های دارای قالب اختصاصی پیام‌نگار و فرستندهٔ منطبق با شمارهٔ ذخیره‌شده را پردازش می‌کند. در نتیجه:

- پیامک‌های عادی را نمی‌خواند و مدیریت نمی‌کند.
- نسخهٔ رمز‌شدهٔ فریم‌ها ممکن است در برنامهٔ پیامک معمول گوشی هم دیده شود.
- متن پیام و عبارت محرمانه در اعلان نمایش داده نمی‌شوند.
- اگر مجوز دریافت پیامک یا اعلان فعال نباشد، قابلیت مربوطه کار نخواهد کرد.

## build

ساخت APK آزمایشی Debug در GitHub Actions انجام می‌شود. این کار build را تأیید می‌کند، نه نصب، مجوزها یا عملکرد SMS روی گوشی واقعی.

برای build محلی Android Studio و Android SDK 36، به JDK 17 و Gradle 9.6.0 نیاز است. این سورس فایل `gradle-wrapper.properties` را دارد، اما اسکریپت‌ها و فایل باینری Gradle Wrapper در این محیط قابل تولید نبودند. اگر Gradle 9.6.0 نصب است، یک‌بار در ریشهٔ پروژه اجرا کنید:

```bash
gradle wrapper --gradle-version 9.6.0
```

**برای نسخه‌ای که قرار است روی گوشی‌ها نصب شود و بعداً به‌روزرسانی شود، باید از اولین نصب یک کلید امضای Release ثابت داشته باشید.** کلید امضا را با دستور زیر در رایانهٔ خودتان بسازید؛ رمز را خودتان تعیین کنید و فایل JKS و رمز آن را جداگانه و امن پشتیبان بگیرید:

```powershell
.\tools\create-signing-key.ps1
```

سپس این چهار مقدار را در فایل Gradle سراسری کاربر، معمولاً `%USERPROFILE%\.gradle\gradle.properties` در ویندوز، قرار دهید. مسیر نمونه را با مسیر واقعی keystore عوض کنید:

```properties
PAYAM_RELEASE_STORE_FILE=C:/Users/USER/Documents/PayamNegar/payam-negar-release.jks
PAYAM_RELEASE_STORE_PASSWORD=YOUR_STORE_PASSWORD
PAYAM_RELEASE_KEY_ALIAS=payam-negar-v1
PAYAM_RELEASE_KEY_PASSWORD=YOUR_KEY_PASSWORD
```

این فایل و keystore را به GitHub نفرستید. بعد از تنظیم، در ریشهٔ پروژه اجرا کنید:

```bash
gradle :app:assembleRelease
```

APK امضاشده در مسیر زیر ساخته می‌شود:

```text
app/build/outputs/apk/release/app-release.apk
```

روی هر دو گوشی همین APK را با همان فرمان ADB بخش نصب، نصب کنید. برای نسخهٔ دوم فقط `versionCode` را افزایش دهید و دقیقاً از همین keystore و alias استفاده کنید؛ در غیر این صورت نصب به‌روزرسانی ممکن نیست. APK نوع Debug شناسهٔ بسته و امضای متفاوت دارد؛ برای نصب اصلی و حفظ امکان به‌روزرسانی از آن استفاده نکنید.

فایل workflow در `.github/workflows/android-apk.yml` برای بررسی build و تولید APK نوع Debug در GitHub Actions قرار دارد. خروجی Debug آن صرفاً artifact توسعه است و به‌دلیل امضای CI نباید APK اصلی دو گوشی قرار بگیرد. سورس Android در شاخهٔ مستقل `android-native-v1` نگهداری می‌شود؛ شاخهٔ `main` و نسخهٔ وب نباید با تغییرات این شاخه دست‌کاری شوند.

## آزمون‌هایی که در این محیط اجرا شدند

آزمون‌های Java خالص (بدون Android SDK) با موفقیت اجرا شدند:

- رمزگذاری و رمزگشایی رفت‌وبرگشت
- ردشدن عبارت اشتباه
- اعتبارسنجی بستهٔ رمز‌شده
- ساخت فریم‌ها و بازسازی بستهٔ چندبخشی
- کنترل قالب فریم‌ها و طول محافظه‌کارانهٔ ۱۴۰ نویسه
- نرمال‌سازی شماره با ارقام فارسی
- رمزگشایی بستهٔ Java توسط WebCrypto
- رمزگشایی بستهٔ WebCrypto توسط Java

اجرای آزمون‌های خالص:

```bash
javac -encoding UTF-8 -d build/pure-test \
  app/src/main/java/ir/tahmuresi/payamnegar/CryptoEngine.java \
  app/src/main/java/ir/tahmuresi/payamnegar/SmsPacketProtocol.java \
  app/src/main/java/ir/tahmuresi/payamnegar/PhoneNumbers.java \
  tools/PureJavaSelfTest.java
java -cp build/pure-test ir.tahmuresi.payamnegar.PureJavaSelfTest
```

برای آزمون رفت‌وبرگشت با WebCrypto/Node.js، فایل‌های `tools/crosscheck-webcrypto.mjs` و `tools/DecryptPacket.java` هم همراه سورس هستند.

## وضعیت آزمون و گام‌های باقی‌مانده

1. نصب APK آزمایشی با ADB روی هر دو گوشی و تأیید مجوزهای `SEND_SMS` و `RECEIVE_SMS`.
2. بررسی رفتار راهنمای Restricted Settings روی نسخه و رابط کاربری واقعی گوشی. مجوز اعلان اختیاری است.
3. آزمون ارسال و دریافت واقعی بین دو اپراتور/دو گوشی.
4. آزمون دریافت در پس‌زمینه، اعلان، پیام چندبخشی، ترتیب نامنظم قطعات، قطعهٔ تکراری و قطع/وصل شبکهٔ اپراتور.
5. بررسی مصرف هزینهٔ پیامک، رفتار دوسیم‌کارته و سازگاری سازنده‌های گوشی.
6. بازبینی امنیتی قبل از استفاده برای اطلاعات حساس.

**این پروژه نمونهٔ اولیهٔ خصوصی است و ممیزی امنیتی مستقل نشده است؛ برای تبادل اطلاعات بسیار حساس یا اضطراری نباید به آن به‌عنوان ابزار امنیتی ممیزی‌شده اتکا کرد.**
