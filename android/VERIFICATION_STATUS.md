# وضعیت راستی‌آزمایی — پیام‌نگار امن Android v1

آخرین بازبینی: 2026-10-30

## نتیجهٔ کلی

این پوشه یک **پروژهٔ سورس مستقل و پیش‌نویس اجرایی نسخهٔ اول** است. هنوز نباید آن را APK آمادهٔ نصب یا محصول تأییدشده دانست. نسخهٔ وب قبلی و مخزن GitHub آن تغییر نکرده‌اند.

## مواردی که واقعاً در این محیط آزموده شدند

- اجرای آزمون Java خالص برای رمزگذاری/رمزگشایی رفت‌وبرگشت.
- ردکردن عبارت نادرست و دادهٔ رمز‌شدهٔ دست‌کاری‌شده.
- متفاوت‌بودن salt و IV در دو رمزگذاری متوالی.
- تقسیم بسته به فریم‌های SMS، کنترل قالب و طول هر فریم، و إعادة تجمیع فریم‌ها.
- نرمال‌سازی ارقام فارسی شمارهٔ تلفن و اعتبارسنجی قالب بین‌المللی.
- آزمون متقابل قالب رمزنگاری: WebCrypto بستهٔ Java را رمزگشایی کرد و Java بستهٔ WebCrypto را رمزگشایی کرد.
- تجزیهٔ XML برای AndroidManifest و styles.xml.

فرمان آزمون خالص:

```bash
./tools/run-pure-tests.sh
```

خروجی آخرین اجرا:

```text
PASS: crypto round-trip, wrong-key rejection, SMS frames, reassembly, and phone formatting
PASS: WebCrypto decrypted Java packet; reciprocal WebCrypto packet created for Java decrypt test.
PASS: Java decrypted WebCrypto envelope
```

## مواردی که هنوز آزموده نشده‌اند

- Gradle build واقعی و تولید APK.
- نصب APK روی گوشی Android واقعی.
- فعال‌شدن مجوزهای SMS از طریق ADB روی هر دو دستگاه و رفتار سازنده/نسخهٔ Android.
- ارسال و دریافت SMS واقعی بین دو اپراتور و دو سیم‌کارت.
- دریافت پس‌زمینه در حالت‌های مختلف مصرف باتری، راه‌اندازی مجدد دستگاه و توقف اجباری برنامه.
- نمایش اعلان روی گوشی واقعی و رفتار اعلان در تنظیمات حریم خصوصی دستگاه.
- دریافت فریم‌ها با ترتیب نامنظم، تکرار/حذف فریم و تطبیق شمارهٔ فرستنده در شبکهٔ واقعی.
- تست امنیتی مستقل.

## دلیل build نشدن APK در این محیط

در محیط اجرای فعلی Java موجود است، اما Android SDK، فایل `android.jar`، Gradle و ADB در دسترس نیستند. بنابراین اجرای Gradle build و تأیید APK از این محیط ممکن نبود. نبودن APK عمدی پنهان نشده و هیچ فایل APK آزمایش‌نشده‌ای به‌عنوان خروجی نهایی ارائه نمی‌شود.

## پیش‌نیاز نصب خصوصی

مجوزهای `SEND_SMS` و `RECEIVE_SMS` در Android از نوع restricted هستند. برای سناریوی نصب خصوصی دو دستگاه، مسیر در نظر گرفته‌شده نصب از طریق ADB با allowlist شدن مجوزهاست؛ نصب با لمس APK به‌تنهایی مسیر تضمین‌شده‌ای نیست. پس از build باید وضعیت مجوزها روی هر گوشی داخل برنامه بررسی شود.

## محدودهٔ محصول

- v1: فقط SMS، دو کاربر، بدون حساب و سرور.
- v2: ارتباط اینترنتی/وب، انتخاب اختیاری بستر و احتمالاً QR برای تبادل/تأیید کلید؛ هنوز پیاده‌سازی نشده.
- عبارت محرمانه خارج از برنامه تبادل می‌شود؛ در SMS یا دیتابیس نوشته نمی‌شود.
- دیتابیس محلی فقط بستهٔ رمز‌شده و metadata لازم را نگه می‌دارد.


## تغییر رابط کاربری در ۳۰ اکتبر ۲۰۲۶

طبق درخواست کاربر، صفحهٔ اصلی جمع‌وجور شد:

- سربرگ فقط عنوان «پیام‌نگار امن» را نشان می‌دهد؛ زیرعنوان و خط تزئینی حذف شدند.
- ردیف مخاطب/شماره به یک ردیف فشرده تبدیل شد: فهرست مخاطب ذخیره‌شده، دکمهٔ افزودن و ورودی مستقیم شماره. در نسخهٔ فعلی فقط یک مخاطب ذخیره‌شده پشتیبانی می‌شود که با محدودهٔ دونفرهٔ نسخهٔ اول سازگار است.
- کارت مستقل مجوزها و متن‌های توضیحی اضافی از رابط حذف شدند. بررسی مجوزهای ضروری در منطق ارسال باقی است؛ مجوزهای محدودشدهٔ SMS باید طبق راهنمای نصب با ADB از مسیر نصب مجاز شوند.
- بخش عبارت محرمانه، دکمه‌های بازکردن/قفل و بخش گفتگو ساده و فشرده شدند.
- رنگ‌بندی از سرمه‌ای/طلایی به طیف خنثیِ سبز-خاکستری، کرم و آجری تغییر کرد.
- فایل پیش‌نمایش `preview/index.html` نیز با همین چیدمان هماهنگ شد.

آزمون‌های Java خالص پس از این تغییرات دوباره اجرا شدند و موفق بودند. این آزمون‌ها رابط Android، build کامل APK یا رفتار واقعی SMS روی گوشی را تأیید نمی‌کنند. Android SDK/Gradle/ADB در این محیط در دسترس نبودند؛ بنابراین APK ساخته یا روی گوشی نصب و آزمایش نشده است.


## اصلاح رفتار قفل خودکار — ۳۰ اکتبر ۲۰۲۶

طبق تصمیم کاربر، کنترل دستی «قفل گفتگو» از رابط Android و پیش‌نمایش حذف شد. فقط «بازکردن گفتگو» باقی مانده است. قفل‌کردن، رفتار داخلی برنامه است: در `MainActivity.onStop()` با خروج Activity از وضعیت قابل‌مشاهده، عملیات بازکردنِ درحال اجرا بی‌اعتبار می‌شود، `sessionPassphrase` پاک می‌شود، ورودی عبارت محرمانه و پیش‌نویس ارسال‌نشده خالی می‌شوند و متن پیام‌های رمزگشایی‌شده از نمای گفتگو برداشته می‌شود. برای ادامه، کاربر باید دوباره عبارت محرمانه را وارد کند. هیچ دکمهٔ دستی برای قفل‌کردن در UI وجود ندارد.

این تغییر سورس و پیش‌نمایش را اصلاح می‌کند؛ build APK و آزمون چرخه‌عمر روی گوشی واقعی همچنان انجام نشده است. همچنین `onStop()` قفل را هنگام رفتن کامل Activity به پس‌زمینه اجرا می‌کند؛ رفتار در حالت‌های چندپنجره‌ای/تصویر در تصویر و نسخه‌های مختلف Android نیازمند آزمون روی دستگاه است.
